# Internationalization

## Languages

- **English** is the default language, the reference catalog and the fallback. It is bundled with
  the app; every other catalog is a separate file of the build, loaded on demand.
- The candidates are the 24 official languages of the European Union (`euLanguages` in
  `src/i18n/index.ts`, in the EU's protocol order, each named in its own language). Only those with
  a catalog are offered (`languages`): adding a language means adding its file. Today: English,
  French, German and Spanish. The German and Spanish catalogs have not been reviewed by native
  speakers yet.
- **The choice is made per device**, and also saved on the profile (`ProfileService.SetLanguage`)
  so that it follows the profile to devices that chose nothing. In order: the device's choice, the
  profile's language, the browser's (the first offered language it asks for), the server's before
  any login (`GetServerInfo.language`), English. Only the device's choice is stored locally.
- The picker is in "My account" and inline on the entry screens. Each language is named in its
  own language, and the label also says "language", for whoever cannot read the language shown.
- A change applies at once, without a reload: texts, the tab title and `<html lang>`.

## The tool

i18next and react-i18next: plurals for each language, rich text (`<Trans>`), language changes
without a reload, typed keys. Doing this by hand would mean rewriting all of it.

- Catalogs live in `src/i18n/locales/<code>.json`, grouped by screen or area.
- Keys are typed from the English catalog (`i18next.d.ts`): an unknown key does not compile.
- The catalog of the device's language is loaded before the first render (`ready`, awaited by
  `main.tsx`), so there is no flash of English.
- **Parity is tested** (`locales.test.ts`): every catalog has the keys of English, no more, no
  less (plural suffixes aside), the same variables and `<Trans>` tags, every plural form its
  language needs according to `Intl.PluralRules`, and no empty text.

## Writing a text

- In a component: `const { t } = useTranslation()` (the component re-renders on a change).
- Outside a component, or in an effect: `i18n.t()`, read at call time.
- A constant list of labels holds **keys**, translated when displayed.
- Dates, numbers and lists go through `Intl` in the current language: `locale()` (the browser's
  variant when it is of the same language, "fr-CA", otherwise the chosen region, "fr-FR"),
  `num()` and `list()`.
- The metadata language of a library is chosen among the 24 EU languages, named in the interface
  language, the interface language by default.

## Texts composed by the server

The server composes no sentence (server: docs/design/i18n.md). Every text it writes is a key,
parameters and sometimes a list of other texts (a `Text`, the `x_text` twin of each field it
writes), and every expected error has a code and parameters (`ErrorDetail`). It also writes a
fallback text in the language of the request; each call sends `Accept-Language`.

The client translates them with the **server's catalogs**, flat and in the server's own syntax
(`{name}`, `{seconds:duration}`, `{bytes:bytes}`, `{seconds:clock}`, `{flag:onoff}`, `{list}`):
`src/i18n/server/<code>.json`. English and French are copied from the server repository by
`pnpm gen` and checked by `pnpm gen:check`; the other languages are translated here. They load
with the interface catalogs and stay outside i18next, because some keys are also the prefix of
others (`activity.scan`, `activity.scan.added`).

- `serverText(text)`: home row titles, the activity log, the reasons of a transcode, errors from
  Sonarr and Radarr, problems of a Jellyfin import, OpenID Connect refusals, the end of a watch
  party.
- `named(name, text)`: names the server makes up when nothing better exists (season, episode,
  unknown artist or album, volume, built-in themes).
- `errorMessage(err)`: an error's `ErrorDetail.code`, with its causes as a list. A route outside
  Connect (file, image) gives its code in the `Laterna-Error` header (`httpErrorMessage`).

A key the language does not have keeps the server's text. Data (NFO files, library names, titles)
and the server's technical logs are shown as they are.

## Adding a language

Add its interface catalog **and** its server catalog; the tests list what is missing. A new
server text or error code arrives with `pnpm gen` (English and French), and `pnpm check` reports
what the other languages lack.

The developer-facing parts stay in English only: theme hooks and the theme authors' guide,
comments, the development tools, messages meant for developers (the accessibility audit, internal
errors).
